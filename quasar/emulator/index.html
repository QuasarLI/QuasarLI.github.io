Android testing · planned procedure

Keep the emulator on D:.

This is a walkthrough for later—not a record of completed testing. No emulator, system image, virtual device, Windows feature, or firmware setting was installed or changed while preparing it.

Compatibility boundary: Quasar v0.4.0 does not support Android configurations that require 16 KB memory pages. Use the emulator procedure below only for supported 4 KB-page testing. Run Android Emulator directly on Windows with Windows Hypervisor Platform, and use a disposable test device with no personal account or data. An emulator is not a security boundary and does not replace physical ARM64-device testing.

1. Check the host first

In Task Manager → Performance → CPU, confirm Virtualization: Enabled. If it is disabled, enable Intel VT-x or AMD SVM in firmware. When you are ready to proceed, enable Windows Hypervisor Platform in “Turn Windows features on or off” and restart if requested. Do not weaken Windows security to accommodate an obsolete acceleration driver.

2. Direct large files to D:

$env:ANDROID_HOME = "D:\Tools\android-sdk"
$env:ANDROID_USER_HOME = "D:\Tools\android-user"
$env:ANDROID_AVD_HOME = "D:\Tools\android-avd"
$env:GRADLE_USER_HOME = "D:\Tools\gradle-home"
$env:JAVA_HOME = "D:\Tools\jdk-17.0.20.1+1"

New-Item -ItemType Directory -Force `
    $env:ANDROID_USER_HOME, $env:ANDROID_AVD_HOME | Out-Null

These PowerShell variables last for that terminal only. If ANDROID_SDK_ROOT already exists, do not leave it pointing to a different SDK. Do not move or replace Quasar’s Android release keystore; the private app-signing key is unrelated to disposable emulator data.

3. Download one emulator image when ready

$sdkmanager = "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat"
& $sdkmanager --sdk_root="$env:ANDROID_HOME" --licenses
& $sdkmanager --sdk_root="$env:ANDROID_HOME" `
    "emulator" "platform-tools" "system-images;android-35;google_apis;x86_64"
& "$env:ANDROID_HOME\emulator\emulator.exe" -accel-check

Review Google’s license prompts yourself. Allow roughly 15–25 GB on D: for an initial setup. Prefer an x86_64 image and confirm that every native dependency in the APK includes x86_64 support.

4. Create and start a disposable phone

$avdmanager = "$env:ANDROID_HOME\cmdline-tools\latest\bin\avdmanager.bat"
& $avdmanager create avd -n "Quasar_API35" `
    -k "system-images;android-35;google_apis;x86_64" `
    -p "D:\Tools\android-avd\Quasar_API35.avd"

& "$env:ANDROID_HOME\emulator\emulator.exe" `
    -avd "Quasar_API35" -gpu auto -memory 2048 -no-snapshot

Answer “no” if asked to create a custom hardware profile. Do not use overwrite options against an existing virtual device.

5. Install the APK from a verified ZIP

First verify the downloaded ZIP against its Sigstore bundle and extract it on D:. Then target the emulator explicitly:

$adb = "D:\Tools\android-sdk\platform-tools\adb.exe"
& $adb devices -l
& $adb -s emulator-5554 shell getprop ro.product.cpu.abilist
& $adb -s emulator-5554 shell getconf PAGE_SIZE
& $adb -s emulator-5554 install -r "D:\Quasar-Test\Quasar-Android-Free-0.4.0.apk"

Replace the serial and path with your actual values. Android requires the same package ID and APK signing certificate for an in-place update; a debug-signed build cannot update a release-signed install.

6. Run meaningful checks

  1. Open every screen at normal and large text sizes; inspect contrast, clipping, scrolling, and background texture.
  2. Use throwaway files only. Back up and restore each advertised format, then compare restored file hashes.
  3. Exercise wrong passwords, truncated archive copies, cancellation, insufficient space, denied access, offline mode, and update failure. Errors should be explicit, never success-shaped.
  4. Confirm each edition’s monthly limits, that paid activation removes ads, and that an affiliate request occurs only after an intentional click.
  5. Test a same-key upgrade without uninstalling and confirm settings, usage, and license state remain.

Limits of the result

  • An x86_64 emulator does not prove ARM64 native-library compatibility or behavior on manufacturer-modified Android builds.
  • Do not use a successful 4 KB API 35 emulator run to infer 16 KB support. Inspection found that a packaged native dependency does not meet current Android 16 KB guidance, so 16 KB-page configurations are unsupported for v0.4.0.
  • USB workflows, recovery mode, rooted-device behavior, OEM restrictions, and real hardware backup/restore still require appropriate physical devices.
  • The guest can use the network and reach some host services. It is not an isolated malware-analysis environment.
